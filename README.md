# Сайт міжнародних перевезень Україна ↔ Європа

Односторінковий сайт для реклами Facebook / Instagram. Заявки з форми автоматично надходять у вашу Telegram-групу через Telegram Bot API. Токен зберігається лише на сервері.

## Що всередині

```
public/            сайт (статичні файли)
  index.html       сторінка
  style.css        дизайн
  app.js           форма, країни/міста, Meta Pixel
  data.js          країни та міста (спільний файл для сайту й сервера)
  img/bus.jpg      ← сюди покласти фото автобуса (див. нижче)
api/
  lead.js          приймання заявки → Telegram sendMessage
  config.js        віддає браузеру лише META_PIXEL_ID
vercel.json        конфігурація хостингу
.env.example       шаблон змінних
check-telegram.js  перевірка токена, пошук ID групи, тестове повідомлення
preview.js         локальний запуск для перегляду
build-preview.js   збирає один автономний index.html для перегляду (node build-preview.js)
test/lead.test.js  тести серверної функції
```

## Підключення Telegram і Pixel: коротко

Усі свої дані ви вписуєте лише в **одному місці**: файл `.env` (локально) або Environment Variables на хостингу (Vercel). У код сайту нічого вставляти не треба.

| Що | Змінна | Де взяти |
|---|---|---|
| Токен бота | `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| ID групи | `TELEGRAM_CHAT_ID` | група з ботом → скрипт `check-telegram.js` покаже ID |
| Pixel ID (Meta) | `META_PIXEL_ID` | Meta Events Manager → Data sources → ваш піксель (лише цифри) |

**Перевірка на своєму комп'ютері (потрібен Node.js):**
1. Скопіюйте `.env.example` у файл `.env` і впишіть `TELEGRAM_BOT_TOKEN=ваш_токен`.
2. Додайте бота в групу й напишіть там будь-яке повідомлення.
3. Запустіть `node check-telegram.js`: скрипт перевірить токен і покаже ID групи (наприклад `-1001234567890`).
4. Впишіть його в `.env` як `TELEGRAM_CHAT_ID=-1001234567890` і запустіть `node check-telegram.js` ще раз: у групу прийде тестове повідомлення. Якщо воно прийшло, Telegram налаштовано правильно.
5. Для повної перевірки форми: `node preview.js` (без `--dry`), відкрийте http://localhost:3000 і надішліть заявку.
6. Для Pixel додайте в `.env` `META_PIXEL_ID=цифри`.

**Для публікації:** ці самі три змінні додайте в Vercel (Settings → Environment Variables) і зробіть Redeploy. Файл `.env` нікому не передавайте і не публікуйте.

## Локальний перегляд на вашому комп'ютері

1. Встановіть Node.js (nodejs.org, версія LTS), якщо його ще немає.
2. Розпакуйте архів, у терміналі (Windows: PowerShell або cmd; Mac: Terminal) перейдіть у папку `site`.
3. Запустіть: `node preview.js --dry`
4. Відкрийте в браузері http://localhost:3000

Режим `--dry` призначений лише для перегляду: заявки **не** йдуть у Telegram, а друкуються в терміналі, а сайт показує повідомлення про успіх. Перегляд без `--dry` (`node preview.js`) надсилає заявки в Telegram тільки якщо створено файл `.env` (скопіюйте `.env.example`) із вашими токеном і chat id; інакше форма покаже повідомлення про невдачу.

Лише подивитися дизайн можна й без запуску: відкрити `public/index.html` подвійним кліком. Усе, крім форми, буде працювати.

## 1. Створіть Telegram-бота і групу

1. У Telegram відкрийте **@BotFather** → `/newbot` → задайте назву й ім'я. Отримаєте **токен** вигляду `123456789:AAAA...`.
2. Створіть групу для заявок і **додайте туди бота**.
3. Напишіть у групі будь-яке повідомлення.
4. Дізнайтесь **chat id** групи: відкрийте у браузері  
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`  
   і знайдіть `"chat":{"id":-100...}`. Це число (зазвичай від'ємне, починається з `-100`) і є `TELEGRAM_CHAT_ID`.  
   Якщо `result` порожній — надішліть у групу ще одне повідомлення й оновіть сторінку.
5. Якщо у групі бот не бачить повідомлень, у @BotFather виконайте `/setprivacy` → бот → *Disable*.

## 2. Куди вставляти токен та ID групи

Ніколи не вставляйте їх у файли сайту й не публікуйте в GitHub. Вони додаються як **змінні середовища хостингу**:

| Змінна | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від BotFather |
| `TELEGRAM_CHAT_ID` | id групи (напр. `-1001234567890`) |
| `META_PIXEL_ID` | ID пікселя Meta (лише цифри) |
| `ALLOWED_ORIGIN` | необов'язково: ваш домен, напр. `https://your-domain.com` |

## 3. Публікація (Vercel, безкоштовно)

1. Завантажте папку проєкту в репозиторій GitHub (файл `.env` у репозиторій не додавайте).
2. На vercel.com: **Add New → Project** → оберіть репозиторій → **Deploy** (налаштування за замовчуванням).
3. **Settings → Environment Variables** → додайте змінні з таблиці вище → **Redeploy**.
4. **Settings → Domains** → підключіть свій домен.

Альтернатива без GitHub: встановіть Vercel CLI (`npm i -g vercel`) і виконайте `vercel --prod` у папці проєкту.

Локальний запуск: `vercel dev` (змінні візьме з `.env`, створеного з `.env.example`).

> Важливо: простий статичний хостинг (GitHub Pages, звичайний хостинг без Node.js) **не підійде** — там немає серверної частини, і заявки не дійдуть. Потрібен хостинг із serverless-функціями (Vercel; для Netlify функції доведеться перенести у формат Netlify).

## 4. Перша перевірка після налаштування

1. Відкрийте опублікований сайт, заповніть форму, надішліть.
2. Заявка має з'явитись у Telegram-групі.
3. Якщо ні — сайт покаже повідомлення про помилку з пропозицією зателефонувати. Причини зазвичай такі: неправильний токен або chat id; бота не додано в групу; змінні додані, але не зроблено Redeploy. Деталі помилки дивіться у Vercel → **Logs**.

## 5. Фотографії

У проєкт уже додано 4 фото (у `public/img/`), вирізані з наданого колажа:

| Файл | Де показується |
|---|---|
| `bus.jpg` | головний екран (автобус біля гір) |
| `bus2.jpg` | блок «Про компанію» (автобус на тлі європейського міста) |
| `salon.jpg` | галерея «Комфорт у дорозі»: салон із сидіннями |
| `comfort.jpg` | галерея: сидіння та вікна салону |

- Колаж мав кадри невеликого розміру (близько 550 px завширшки), тому їх збільшено до 1200–1600 px. На великих екранах головне фото трохи м'яке. Щоб було чіткіше, замініть файли оригіналами тих самих кадрів у більшому розмірі (бажано 1920 px і більше), зберігши імена.
- **Фото водія за кермом у колажі не було.** Щоб додати: покладіть `driver.jpg` (1200×800) у `public/img/` і в `public/index.html` у блоці `class="gal"` додайте рядок  
  `<figure class="photo" data-photo hidden><img src="img/driver.jpg" alt="Водій автобуса за кермом" width="1200" height="800" loading="lazy"><figcaption>Досвідчені водії</figcaption></figure>`
- Коли файл `bus.jpg` є, векторний автобус у шапці автоматично ховається.
- Фото створені ШІ. Meta може вважати оманливою рекламу, де показано автобус, який не збігається з вашим реальним. Для реклами краще додати хоча б одне справжнє фото вашого транспорту.

- **Автоматичне надсилання заявок у Viber не підключено.** Для цього потрібен Viber Business / Chatbot API: акаунт бота (у Viber Admin Panel), токен бота та окремий публічний вебхук. Також Viber дозволяє боту писати лише тим, хто підписався на нього, і надсилати в групи обмежено. Тому надійний канал — Telegram, він працює незалежно від Viber. Якщо захочете Viber-бота, його можна додати окремо в `api/lead.js` після відправки в Telegram.

## 8. Meta Pixel і cookies: як підключити пізніше

Зараз піксель **вимкнений** (ID не заданий) і банер cookies не показується, бо погоджувати поки нічого. Щоб підключити:

1. У Meta Events Manager створіть піксель і скопіюйте його ID (число).
2. На хостингу (Vercel → Settings → Environment Variables) додайте `META_PIXEL_ID` = це число. Зробіть **Redeploy**. Код сайту змінювати не треба.
3. Після цього на сайті з'явиться банер cookies. Піксель вантажиться **лише якщо відвідувач натиснув «Прийняти»**. Після «Відхилити» нічого не завантажується. Внизу сторінки з'являється посилання «Налаштування cookies», щоб змінити вибір.
4. Події: `PageView` одразу після згоди, `Lead` один раз після того, як сервер підтвердив, що Telegram прийняв заявку (при помилці `Lead` не відправляється).
5. Перевірка: розширення **Meta Pixel Helper** у Chrome або Events Manager → Test Events. Натисніть «Прийняти», надішліть тестову заявку.

Юридично: банер і політика конфіденційності є технічною основою, але чи достатньо їх для ваших країн, вирішує юрист.

## 9. Відгуки

Блок відгуків у `index.html` (`<section id="reviews" hidden>`) прихований. Коли з'являться **реальні** відгуки: додайте три `<blockquote class="review">` усередині блоку (приклад у коментарі) і приберіть атрибут `hidden`. Перед публікацією отримайте згоду авторів.

## 10. Переваги (Wi-Fi, кондиціонер, опалення тощо)

Ці шість карток взято з вашого завдання. Переконайтесь, що кожна відповідає реальній комплектації автобусів, а зайве видаліть у блоці `id="advantages"`. Це важливо для реклами: Meta відхиляє оголошення з недостовірними обіцянками.

## 11. Захист від спаму

Приховане поле-пастка (honeypot); перевірка часу заповнення (форма не приймається раніше ніж за 3 секунди); обмеження 5 заявок за 10 хвилин з однієї IP-адреси (у serverless працює частково, оскільки пам'ять функцій не спільна); серверна валідація всіх полів, включно з маршрутами лише Україна ↔ Європа; екранування HTML у повідомленні Telegram. Для дуже великого потоку ботів можна додати Cloudflare Turnstile.

## 12. SEO

У `index.html` є title, description, Open Graph, розмітка schema.org. Після публікації додайте: `og:image`, canonical-посилання зі своїм доменом і `sitemap.xml`. Файл `robots.txt` уже є.

## 13. Політика конфіденційності

Це шаблонний текст у спливаючому вікні на тій самій сторінці. Вона не є юридичною консультацією: перегляньте її і за потреби доповніть назвою компанії та контактними даними.

## Тести

`npm test` (потрібен Node.js 18+) перевіряє серверну функцію з імітацією Telegram: успіх, помилку Telegram, недоступність мережі, відхилення неправильних маршрутів і даних, honeypot, ліміт запитів.
